# 운영 기록 (Runbook)

사고 대응·설정·오류 해결 기록을 모으는 곳입니다.
**새벽 3시에 당황한 상태에서 읽을 문서**라고 생각하고 씁니다.

## 왜 이렇게 쓰는가

자주 안 하는 작업은 **반드시 잊어버립니다.** 숙련자도 3개월 전에 자기가 뭘 했는지 기억 못 합니다.
차이는 기억력이 아니라 **적어뒀는지**입니다.

그리고 사례가 아니라 **원리**를 적습니다.

| 수준 | 적힌 것 | 새 오류를 만나면 |
|---|---|---|
| 사례만 | "X가 나오면 Y를 실행" | 대응 불가 |
| **원리까지** | "리눅스는 실행 방법이 등록돼야 실행한다" | **짐작 가능** |

## 파일 규칙

- 한 파일 = 한 주제
- 파일명은 영문 소문자 + 하이픈 (`wsl-interop-exec-format-error.md`)
- 아래 템플릿을 지킵니다 → 나중에 DB 컬럼으로 그대로 옮겨집니다

## 템플릿

```markdown
---
제목:
분류: 설정 | 오류대응 | 백업 | 보안 | 배포
태그: wsl, systemd
발생일: YYYY-MM-DD
심각도: 낮음 | 보통 | 높음
---

## 증상
무엇이 어떻게 안 되는가. 오류 메시지는 **그대로** 붙여넣기.

## 원인
왜 이런 일이 생겼는가. ← **가장 중요한 칸.** 여기가 비면 사례집일 뿐입니다.

## 확인 방법
원인을 확인하는 명령. 결과 예시도 함께.

## 조치
실제로 한 것. 되돌리는 방법도 함께.

## 재발 방지
구조를 어떻게 바꿨는가. 없으면 "없음"이라고 적기.

## 배운 것
다른 상황에도 적용되는 일반 원리.
```

## 왜 이 항목들인가

| 항목 | 이유 |
|---|---|
| 증상 | 나중에 **검색할 때 쓰는 말**. 오류 메시지 원문이 검색어가 됩니다 |
| **원인** | 이게 있어야 안 겪어본 문제에도 대응됩니다 |
| 확인 방법 | 급할 때 복사해서 바로 실행 |
| 조치 | 되돌리는 법이 없으면 실행하기 무섭습니다 |
| 재발 방지 | 같은 실수를 반복하지 않기 위해 |
| 배운 것 | 사례를 지식으로 바꾸는 칸 |
