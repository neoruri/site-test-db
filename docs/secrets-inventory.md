# 비밀 값 목록 (Secrets Inventory)

> 🔴 **이 파일에는 실제 값을 절대 적지 않습니다.**
>
> 이 저장소는 **공개(Public)** 입니다. 그리고 Git은 지워도 과거 커밋에 남습니다.
> 한 줄 실수가 영구적입니다.
>
> 여기에 적는 것은 **"무엇이 있고 / 어디에 보관되며 / 잃거나 새면 어떻게 하는가"** 뿐입니다.
> **비밀번호·키·토큰·이메일 주소는 적지 않습니다.**

## 왜 이런 목록이 필요한가

사고가 났을 때 막히는 지점은 기술이 아니라 **"그 비밀번호가 어디 있더라"** 입니다.
[`disaster-recovery.md`](disaster-recovery.md) 의 복구 순서는 이 목록이 채워져 있어야 돌아갑니다.

# 1. 목록

⬜ 는 **직접 채우셔야 하는 칸**입니다. 값이 아니라 **보관 장소**를 적으세요.
(예: `비밀번호 관리자`, `금고의 종이 메모`, `USB 잠긴 파일` — `메모장`·`카톡`·`이메일`은 ❌)

## Supabase

| 비밀 | 보관 장소 | 잃으면 | 새면 |
|---|---|---|---|
| **DB 비밀번호** | ⬜ | 🟢 대시보드에서 재설정 | 🔴 **즉시 재설정** |
| **Publishable key** | 코드에 있음 (정상) | 🟢 대시보드에서 확인 | 🟢 **공개돼도 무방** — 보호는 RLS |
| **Secret key** | 🟢 **발급 안 함** | — | 🔴 RLS 무시 — **절대 발급·커밋 금지** |
| **계정 로그인** | ⬜ | 🔴 **프로젝트 접근 불가** | 🔴 전부 장악됨 |
| **관리자 계정**(admin.html용) | ⬜ | 🟡 다른 관리자가 재설정 | 🔴 신청자 개인정보 열람됨 |

> 🔴 **Supabase 계정 로그인 정보가 가장 중요합니다.** 이걸 잃으면 다른 걸 아무리 갖고 있어도
> 프로젝트에 못 들어갑니다. **2단계 인증(2FA)** 을 켜두시고, 복구 코드도 ⬜ 어딘가에 보관하세요.

## 로컬 (WSL)

| 비밀 | 보관 장소 | 잃으면 |
|---|---|---|
| `~/site-backup/.env` | WSL 안, `chmod 600` | 🟢 다시 작성 (내용은 DB 접속 정보) |
| WSL `sudo` 비밀번호 | ⬜ | 🟡 WSL 재설치 |
| 로컬 PostgreSQL `app_user` | 연습용 | 🟢 재생성 |

> ⚠️ **`.env` 는 백업 대상이 아닙니다.** 백업에 섞이면 백업 파일 자체가 비밀이 됩니다.

## 계정

| | 보관 장소 | 잃으면 |
|---|---|---|
| GitHub | ⬜ | 🟡 코드는 로컬에도 있음 |
| Vercel | ⬜ (GitHub 연동) | 🟢 재배포 가능 |

# 2. 보관 규칙

| | |
|---|---|
| ✅ 비밀번호 관리자 (권장) | |
| ✅ 잠긴 파일 / 금고의 종이 | |
| ❌ **메모장·엑셀 파일** | PC가 뚫리면 통째로 |
| ❌ **카톡·이메일 "나에게 보내기"** | 계정 하나 뚫리면 전부 |
| ❌ **소스코드·이 저장소** | 🔴 공개됨 + 이력에 영구 |
| ❌ **화면 캡처** | 🔴 실제로 한 번 새어나간 적 있음 |

> ⚠️ **캡처 주의** — 터미널에 비밀번호 해시·키가 출력된 채로 캡처한 적이 있습니다.
> 출력에 `$`, `sb_secret_`, `BEGIN PRIVATE KEY` 같은 게 보이면 **캡처하지 마세요.**

# 3. 새어나갔을 때 — 순서가 중요합니다

> **먼저 막고, 그다음에 원인을 찾습니다.** 순서를 바꾸면 그동안 계속 새어나갑니다.

```
① 즉시 무효화     키 재발급 · 비밀번호 변경   ← 원인 파악보다 먼저
② 영향 범위 확인  그 키로 무엇이 가능했나
③ 흔적 확인      Supabase 로그 — 실제로 쓰였나
④ 원인 제거      커밋? 캡처? 공유?
⑤ 기록          runbook/ 에 남긴다
```

## 경우별

| 샌 것 | 해야 할 일 |
|---|---|
| **Publishable key** | 🟢 아무것도 — 공개용입니다. 단 **RLS가 제대로인지** 점검 |
| **DB 비밀번호** | 🔴 즉시 재설정 → `.env` 갱신 |
| **Secret key** | 🔴 즉시 폐기·재발급. **이미 전부 열람 가능했다고 가정** |
| **관리자 계정** | 🔴 비밀번호 변경 + `admins` 에서 일단 제거 |
| **커밋에 섞임** | 🔴 값 무효화가 **먼저**. 파일을 지워도 **이력에 남습니다** |

> 🔴 **"지웠으니 괜찮다"는 통하지 않습니다.**
> 공개 저장소에 한 번 올라간 값은 **이미 봇이 수집했다고 가정**하고 무효화하세요.
> 되돌리는 것은 불가능하고, **바꾸는 것만 가능**합니다.
